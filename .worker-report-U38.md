### Implementation and scope

- Atomic requests now use bounded, overlapping block groups in canonical source
  order. An individually over-budget boundary is subdivided into overlapping exact
  source slices; it cannot escape the budget as a singleton.
- Input sizing follows `llm/cost.py`'s conservative one-token-per-UTF-8-byte bound,
  counting rendered prompt, schema and 1,024 tokens for framing. Output sizing
  reserves six tokens per source byte plus per-block/schema expansion. The output
  estimate also constrains group admission, and the configured output budget is
  explicitly passed as the provider generation cap.
- To honor the plan-file restriction, `config.py` is unchanged. The two positive
  integer fields live in `AtomicExtractionSettings` in `distiller.py`, using the
  existing pydantic-settings mechanism (environment and `.env`):
  `FOLIO_INSIGHTS_ATOMIC_INPUT_TOKEN_BUDGET` (32,768 by default) and
  `FOLIO_INSIGHTS_ATOMIC_OUTPUT_TOKEN_BUDGET` (16,384 by default). Stage constructor
  arguments override these. The ordinary orchestrator loads them through its
  existing atomic stage construction. Settings load only when atomic mode is ON;
  even invalid atomic settings cannot affect the legacy path.
- Context-window/413 rejections and output truncation cause strictly smaller retry
  groups, including subdivision of a single long boundary. The oversized request
  is never resent as-is. Recovery emits `oversized_group_split` diagnostics;
  unrecoverable failures retain the existing failure tracker and run-halting
  behavior. Provider transport, routing and retry code are unchanged.
- All groups finish before child/link reconciliation. Exact grounded span plus NFC
  text defines duplicate identity and stable document-level IDs. Duplicate outputs
  merge citations and links; identical text at different source occurrences stays
  distinct. Group-local endpoint IDs remain scoped to that response; cross-group
  aliases resolve only when unambiguous. Rejected local endpoints cannot borrow an
