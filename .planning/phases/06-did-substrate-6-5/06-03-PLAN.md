Ship the CLI surface and the OAuth→DID binding contract that lock SEC-06 / DID-05 /
DID-07 on the critical path, while the web flow defers (D-02). Phase 6 builds the
backend + CLI contract the deferred post-Phase-14 web phase will simply render.

Delivers:
1. **`binding.py`** — `folio-insights did bind` (D-10): a `BindingRecord` +
   `ProofPayload` (Pydantic, extra=forbid) and the `bind()` rules that defeat the
   replay (F3) and GitHub-username-takeover (F7) attacks — bind to the immutable
   OAuth `sub`, require a single-use server nonce (5-min TTL) + ±2-min timestamp +
   binding-endpoint URL in a DID-signed proof-of-control, detect subject changes
   (force re-bind), and stay idempotent on a repeat `(sub, DID)` bind. A
   `NonceStore` seam (in-memory now; Redis in the web phase) mirrors the Phase-5
   in-memory-seam discipline.

   hash (Plan 01) + a human-readable diff, for **all 8 signed-action types** (EC5).
   CLI/API form only — the styled web preview defers (D-02).
3. **`cli.py`** — the `did` Click subgroup (`generate` / `bind` / `sign` / `verify`
   / `preview`) mirroring the Phase-1 `polysemy` subgroup idiom, wired into the root
   `cli`.

This is the last plan in the chain: it exercises the Plan-01 schema and the
Plan-02 signer/verifier end to end through the operator-facing CLI.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OAuth provider -> binding | The OAuth `sub` claim is the only trusted stable identity; email/username are mutable and must never key a binding (F7) |
| attacker -> binding endpoint | A captured proof-of-control payload must not be replayable to hijack a DID binding (F3) |
| operator -> did CLI | Signing happens client-side with the local keyfile; the CLI never transmits a private key |
| domain owner -> did:web binding | did:web binding must prove control of the domain serving did.json before it is accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Spoofing (replay) | binding proof-of-control payload (F3) | mitigate | Single-use server nonce (5-min TTL, atomic consume) + timestamp within ±2 min + binding-endpoint URL inside a DID-signed proof; replayed/stale proof rejected (test_binding_proof). |
| T-06-11 | Spoofing (username takeover) | OAuth identity -> DID binding (F7) | mitigate | Bind to immutable `sub` only; subject-change detection unbinds the old DID and forces a fresh signed re-bind; email/username-keyed bindings refused. |
| T-06-12 | Tampering | idempotency / silent re-bind | mitigate | A repeat (sub, did) bind is a no-op; a different did for the same sub is an explicit conflict/unbind — never a silent overwrite. |
| T-06-13 | Spoofing | did:web domain control | mitigate | did:web binding verifies .well-known/did.json (or DNS) lists the bound key before recording (resolver check). |
| T-06-14 | Information disclosure | did CLI signing | mitigate | Signing is client-side via the local keyfile (Plan 02 keys.py); the CLI never sends or logs a private key. |
| T-06-SC | Tampering (supply chain) | no new deps in this plan | accept | This plan adds NO packages (all deps installed in Plan 01); authlib is used only for `sub`-claim semantics, no new install task here. |
</threat_model>
