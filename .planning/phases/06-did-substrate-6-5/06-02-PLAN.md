<objective>
Build the `src/folio_insights/identity/` crypto core that signs and verifies
attestations across the three DID methods, capturing the signing-time key so
signatures survive key rotation (SEC-05 / exit criterion 3), and enforcing the
absolute no-server-side-keys invariant (DID-06) as a contract test.

Delivers:
1. **`keys.py`** — client-side local keystore extending the Phase-1
   `~/.folio-insights` ed25519/JWK pattern (`polysemy/reviewer.py`): generate/load
   a private key, derive `did:key`, expose the public key for verification. The
   private key never leaves the operator's machine (D-07, DID-06).
2. **`resolver.py` + `cache.py`** — resolve a DID to its verification key:
   `did:key` decode, `did:web` `.well-known/did.json` fetch, `did:plc` via
   `atproto` IdResolver + PLC op-log pinning at `signed_at` (resolve/verify ONLY —
   no genesis/rotation writes, D-08). `DidDocCache` (D-11) snapshots the
   signing-time doc keyed by `(did, signed_at)` so verification uses the historical
   key — the in-memory seam Phase 13 makes persistent.
3. **`signer.py` + `verifier.py`** — real ed25519 `sign_attestation` over the JCS
   `canonical_content_hash` (Plan 01), recording `signing_key_id` +
   `did_doc_snapshot_at` (DID-04); `verify_attestation` resolves the signing-time
   key and checks the signature, caching the result as the `verified` annotation.
4. **Wire `edit_shard_content`'s frozen `signing_key` parameter** to the real
   signer (the Phase-5 D-01 call-site contract is honored, not changed — D-09).

Purpose: Plan 03 (binding + CLI + preview) signs binding proofs and the 8 action
types with this signer and verifies them with this verifier. EC3/EC4 (rotation
survival + no-server-key) are the gates this plan must turn green.
</objective>
