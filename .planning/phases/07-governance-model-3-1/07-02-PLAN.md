<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator commits to `.planning/rfcs/*.md` → CI runs `python -m folio_insights.rfc.lint .planning/rfcs/` | Operator can attempt to slip a status downgrade or skip-stage transition past code review; linter is the CI gate. |
| Git repository (full history) → `subprocess.run(["git","log","--follow",...])` → frontmatter parse | A malicious commit could craft a commit message body that satisfies `Reason:` heuristic falsely; mitigation is the heuristic is documented as a cheap check, not a cryptographic gate (D-22 explicit). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-08 | Tampering | `rfc.lint` walking git history | mitigate | Walk full `git log --follow --reverse` history of each RFC file; refuse non-monotonic status transitions per ALLOWED_TRANSITIONS DAG; CI gate exits 1 on any violation. D-22 spec. **HIGH severity** — RFC status downgrades silently rewrite the community-process audit trail. |
| T-7-09 | Tampering | RFC body-only status edit without rationale | mitigate | D-22 cheap heuristic — a commit whose diff touches `status:` MUST also have either `Reason:` commit-message trailer OR `status_change_reason:` frontmatter line. Refuse otherwise. Medium severity — heuristic catches accidents; sophisticated attackers can craft both, but the audit trail then carries a documented rationale that code-review can scrutinize. |
| T-7-SC | Tampering | new pip dep (PyYAML / python-frontmatter / GitPython) | mitigate | Plan ships stdlib + Pydantic + subprocess only; explicit grep gate `grep -rn "import yaml\|from yaml\|import frontmatter\|from frontmatter\|import git\b" src/folio_insights/rfc/ | grep -v "^#"` returns empty (acceptance criterion). No new package install → no slopsquat surface. |
