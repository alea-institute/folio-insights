# Phase 03.5 Plan 02: Apply the Fix + Restore the Deploy

**Collapsed the silently-ignored nested `railway.toml` to a flat web-only config, corrected `ci/railway.py` for CLI v4.x, and then repaired a cascade of never-before-deployed `Dockerfile.web` latent bugs to land a healthy Railway deploy serving the SvelteKit SPA + bundled corpora.**

## Performance
- **Duration:** ~150 min (most of it diagnosing/fixing latent bugs in a web tier that had never actually been built or deployed on Railway)
- **Completed:** 2026-05-22
- **Tasks:** 2 (Task 1 auto config-fix; Task 2 human-action vars+deploy)
- **Deploys:** several iterative Railway builds; final SUCCESS = commit `197d67a` (deploy `c5e4b32e`)

## Accomplishments
- **railway.toml** flattened to web-only `[build]`/`[deploy]` (Dockerfile.web + /health + restartPolicy). This made config-as-code engage; Railway stopped falling back to the stale `/Dockerfile`.
- **ci/railway.py** image-deploy path fixed for CLI v4.x (`railway add -i <image> -s <svc>`; the v3 `up --image` flag is gone); T-00-19 env=-only token preserved.
- **Live deploy healthy:** `/health` 200, `/` 200 (no `x-railway-fallback`), `/api/v1/corpora` 200 with bundled demo + test1.
- Runtime vars set as masked variables: `LLM_PROVIDER`, `LLM_MODEL` (non-secret). **No API key** — operator chose BYOK over a shared server key.

## Decisions Made
See key-decisions. The dominant theme: **Dockerfile.web had never been built or deployed on Railway** (the nested toml meant Railway always built `/Dockerfile`), so flattening the toml exposed a stack of latent bugs that all had to be fixed to get a healthy deploy.

## Deviations from Plan

The plan assumed Dockerfile.web "just worked" and only `railway.toml` + `ci/railway.py` needed changing. Reality required substantially more, each fix surfaced by the next Railway build and validated locally with Docker before re-pushing:

1. **Corpora bundling (operator-approved):** Dockerfile.web never copied `output/`; without it the viewer would render empty. Added `COPY output/` + `.dockerignore` re-include of `output/{default,demo,test1}`.
2. **owlready2 wheel build failed on Railway** (`int('') ... File exists dist-info`): the JVM reasoner the web never imports. Moved to a `reasoning` extra (worker installs it explicitly → unaffected).
3. **`requirements.lock` branch was incomplete** (no fastapi/uvicorn/project) and `uv pip install .` ran **before** `COPY src/` → empty `folio_insights` package → `ModuleNotFoundError` at boot. Switched Dockerfile.web to the uv path and moved `COPY src/` before the install.
4. **Viewer `/` never worked:** adapter-node SSR server + FastAPI StaticFiles + node/uvicorn on the same `$PORT`. Operator chose SPA — reverted to adapter-static; converted 3 `+page.server.ts` SSR routes to client `+page.ts`; added `SPAStaticFiles` index.html fallback so deep links work.
5. **`SOURCE_DATE_EPOCH=''` on Railway** crashed hatchling's `int()`. Defaulted the ARG to 0.

**Total deviations:** 5 (1 operator-approved scope add, 4 latent-bug fixes). **Impact:** none undermine the goal; all were prerequisites to a deploy that had never actually run. SSR / Gate 4 (QUALITY-04) and the hash-pinned web lock (Plan 05) are explicitly deferred to Phase 20.
