# Phase 03.5 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> **This is an infra/deploy phase: acceptance is live-URL smoke, not the pytest suite.**
> The deployed app's health is proven by hitting live endpoints; `pytest -q` is a
> regression check, not a deploy gate.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest >= 9.0 + pytest-asyncio (existing — `pyproject.toml` `[tool.pytest.ini_options]`) |
| **Config file** | `pyproject.toml` |
| **Quick run command** | `curl -sf "$URL/health" \| jq -e '.status=="ok"'` (live smoke — the real gate) |
| **Full suite command** | `pytest -q` (existing unit tests; NOT a deploy gate) |
| **Estimated runtime** | smoke ~2s per endpoint; deploy/build 10-15 min first build |

`$URL` = `https://folio-insights-production.up.railway.app`

---

## Sampling Rate

- **After every task commit:** `curl -sf "$URL/health"` once a deploy has completed.
- **After every plan wave:** full smoke trio (`/health`, `/`, `/api/v1/corpora`) + Chrome DevTools MCP screenshot of `$URL`.
- **Before `/gsd:verify-work`:** all three smoke endpoints return 200 AND auto-deploy is proven (a push to `master` triggers a fresh build).
- **Max feedback latency:** ~seconds for smoke; one build cycle (~minutes) for deploy-triggered checks.
